输入

独占一行且顶格的 http(s):// 行按订阅链接抓取（走服务端代理设置）； 其余行原样保留缩进合并成一段订阅内容直接解析 —— 分享链接列表、Base64 包裹、Clash YAML（含 JSON 版）、Xray JSON 配置都自动识别。

订阅名称

作为下载文件名（按目标自动补 .yaml / .json / .txt）与配置首行注释； 客户端用 /sub 订阅时，一般会拿它当订阅名。

目标

链接：复制后到 v2rayNG「从剪贴板导入」；订阅：把生成的 API 地址填进「订阅设置」。 这两者都是通用分享链接，http 代理没有链接形态会被跳过； 完整用 v2rayN 的 v2rayn:// 格式，能把 http 节点也带进去（只有 v2rayN / v2rayNG 认）。 注意带 TLS 的 http（https 代理）只有 v2rayN 能生效，v2rayNG 的 http 出站会忽略 TLS。

高级选项
DNS · 写进 clash 的 dns.nameserver；国外优先， 国内解析器在跨境场景容易被污染，不推荐。目前只对 Clash / mihomo 目标生效。
前置代理 · 每行一项，上面的在前，产物是 本地 -> 第 1 项 -> 第 2 项 -> … -> 每个节点。 每项可以是一条分享链接（ss:// vmess:// vless:// trojan:// socks5:// http:// …）， 也可以是订阅里某个节点的名字（可写 @名字）。
后置代理接在节点后面：产物变成 本地 -> … -> 每个节点 -> 第 1 项 -> … -> 目标。 链路字段的含义是「本出站经谁出去」，所以流量落点会变成后置列表的末尾 —— 末尾出站的名字写成 节点 -> 后置，节点自己不改名， 照旧直连（或接在前置链路后面）。于是客户端里选中 节点 -> 后置 得到的就是 本地 -> 节点 -> 后置 -> 目标（即拿节点当入口、拿后置当出口）。 后置每个节点都会克隆一份（第 1 跳必须经各自的节点出去）， 所以 N 个节点配 m 跳会多出 N×m 个出站。
落点：Xray 的 sockopt.dialerProxy / Clash 的 dialer-proxy / sing-box 的 detour；链接类目标（v2rayNG 链接 / 订阅 / 完整）没有该字段， 会告警并忽略。
链路是按 TCP 建的隧道：凡是「经隧道被拨到」的那一跳（前置链路下的节点、后置链路的每一跳） 若是 hysteria2 / tuic / wireguard 或 quic / kcp 传输就连不通（转换时会告警）。
内置规则集 · 勾中即把它的规则展开到下面的表里（按目录顺序）。 目前只对 Clash / mihomo 目标生效。
规则表 · 按表内顺序匹配；点某一行选中后可删除（内置行只读）。
按 回车 即可加入表格；新规则排在最上方。
